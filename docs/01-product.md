# 产品需求

状态：设计基线 v0.1，2026-11-08。

## 1. 用户与核心任务

首位用户是大学生，自用单台 Android 手机，希望还原一天的手机使用过程，在晚间或次日复盘时间去向。产品首先服务个人观察与调整。

用户应能快速回答：

1. 上午、下午、晚上分别用了哪些应用？
2. 刚才那一小时发生了什么，每段持续多久？
3. 一段使用是学习、查资料、聊天还是娱乐？
4. 哪些时候反复拿起手机，哪些连续使用段特别长？
5. 今天与昨天相同时段相比发生了什么变化？

核心价值按顺序为：时间经过清晰、记录可靠、复盘省事、长期可追溯。

## 2. 产品原则

- 自动记录应用使用；复盘时按需补充用途与线下活动。
- 自动数据与用户补充各自保留来源，界面自然区分。
- 默认无需每天填写完整日记，也无需提前建任务或启动计时器。
- 所有分析可追溯到具体区间，显示真实的覆盖范围。
- 使用中性语言呈现事实，例如“22:10 后使用 48 分钟”。
- 纯本地运行，无 INTERNET 权限、云账号、广告、遥测与内容上传。
- 限制收集范围为应用、时序、屏幕与锁屏事件。聊天文本、网页内容、键盘输入与截图均在范围外。

## 3. 第一版范围

| 优先级 | 功能 | 对用户的价值 |
| --- | --- | --- |
| P0 | 日期时间线、24 小时概览、应用会话 | 找到“什么时候干了什么” |
| P0 | 选中任意时间段查看构成 | 复盘一节课、午休或睡前 |
| P0 | 应用详情与使用排行 | 查某个应用的具体使用记录 |
| P0 | 本地持久化、补采、覆盖状态 | 保留长期记录，辨认数据空档 |
| P0 | 简单时段用途标注、备注 | 区分同一应用的不同用途 |
| P0 | 数据导出、手动备份恢复、清空 | 数据可带走、可恢复、可管理 |
| P1 | 周趋势、用途统计、每日复盘摘要 | 回顾持续变化 |
| P1 | 离线活动补记、复盘提醒 | 补充线下经过并养成回顾习惯 |
| P2 | 课表导入、自定义日界线、限额提醒 | 待核心体验稳定后评估 |

第一版完成全部 P0 才称为个人可用版本；P0 内按开发里程碑逐项落地。

## 4. 大学生场景的处理

| 场景 | 产品行为 |
| --- | --- |
| 上课期间多次看手机 | 选中课程时间范围，展示手机使用分钟数、应用与使用轮次 |
| 微信接收课程通知又闲聊 | 应用默认分类供参考，按区间补标“课程事务”或“社交” |
| B站看教学视频 | 可将该区间标为“学习”，保留原始 B站会话 |
| 用电脑做作业时手机息屏 | 显示手机息屏；可补记线下活动“电脑写作业” |
| 连续刷手机到凌晨 | 跨日显示连续会话提示；按自然日分配时长 |
| 忘记打开统计应用数日 | 后台尽量补采，恢复时补齐系统仍可查询的记录 |

“学习”等用途来自用户标注或应用默认映射；应用级分类只作为回顾线索。未使用手机的时段保持设备状态描述，学习、睡眠、运动等含义由用户补充。

## 5. 成功标准

- 打开首页能直接看到今天经过，进入某小时无需翻多级菜单。
- 一次常见复盘操作可完成：选择日期、选择时段、查看构成、添加一句备注。
- 同一统计口径下，时间线、详情、排行和导出结果一致。
- 可回看历史会话，辨认进行中、推算、记录缺失与仅摘要区间。
- 首次授权后即展示系统可提供的数据，说明可回溯范围。

## 6. 初始默认值

首页为今日时间线；自然日 00:00 起算；周一为周起点；应用短片段折叠阈值 10 秒；保留事件 90 天、会话与手动记录长期保存；后台补采目标每小时一次；默认关闭通知。均可按真机体验修订并记录原因。
