# Android 使用记录同步

Android 手机和平板管理、保存和展示自己的使用记录。开启同步后，设备只上传自己的记录。服务器独立保存，各台同账号电脑用这些记录构建多设备仪表盘。换机后新手机有自己的设备身份，旧手机的云端记录在电脑端仍可查阅。

## 启用与范围

在「设置 → 跨设备同步」输入受邀邮箱，获取并填写六位验证码。验证码有效期为五分钟，重发按钮显示服务端给出的等待时间。修改邮箱会清除原邮箱对应的验证码。点「登录」后确认设备名称与首次上传日期，默认从当天起，历史范围另选。关闭同步或退出后本机照常采集，云端已提交记录保留。

登录页同时显示邮箱和验证码。常规手机宽度下，获取和重发按钮放在验证码旁；窄屏或大字体时放到下一行。输入提示在表单内显示，设备名称与历史范围在提交登录前统一确认。

| 本机来源 | 上传 |
| --- | --- |
| 设备区间 | UTC 毫秒，按 UTC 日切分。已解锁可操作为活跃，锁屏和息屏是离线，已知区间内的未知状态为缺口。 |
| 应用会话 | 应用包名、显示名、起止时间及实测或推算。同应用重叠去重，不同应用分屏仍可并行。 |
| 隐私过滤 | 隐藏或排除的应用不上传身份。日记、复盘、标注、原始系统事件和系统历史汇总桶留在本机。 |

## 执行与恢复

- 上传队列与本机采集分离。修订号随安装身份持久保存。服务器事务确认后，清理相应日期与版本。确认丢失时可重试，已确认的同版本同内容不重复计时。
- 已确认内容在现有 Room 同步表中用于判断本日是否发生变化。历史清空时发布删除修订。Android 界面和报表只读取本机采集数据。
- 登录后立即尝试，前台定期检查，采集变化合并后触发。后台使用唯一 WorkManager 定期任务和一次性补齐任务。断网保留队列，恢复联网后补齐。 [Android 定期任务调度](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)
- 上传世代不匹配时重新确认服务器世代，并在用户已选范围内重算本机数据。Android 无权读取账号汇总的下行接口。
- 设备 ID 随机生成。刷新令牌由 Android Keystore 保护，访问令牌只驻留内存。旧版创建的远端表结构保留用于数据库兼容，当前应用不拉取或展示旧镜像。

## 接口与发布

Android 默认连接 `https://kovra.top/tickmark`，与 Windows 使用同一账号服务。测试时可用 Gradle 属性 `tickmarkSyncBaseUrl` 或环境变量 `TICKMARK_SYNC_BASE_URL` 覆盖。正式构建使用 HTTPS，Debug 可用模拟器回环地址。统一的账号、日分片和部署协议见 Tickmark Desktop 的 `docs/sync.md`，服务端由 Tickmark Server 仓库维护。

生产服务已部署。首个受邀邮箱的测试验证码已由 QQ 邮箱服务器接收。用户实际登录需要在客户端重新获取验证码，厂商后台行为需在实际 Android 设备覆盖。
