# Android 应用使用统计与屏幕时间分析工具 (PRD)

## 1. 产品定位与设计目标

- **定位**：一款轻量、极简、完全纯本地运行（Zero-Network）、注重隐私保护的 Android 屏幕使用时间与应用行为精细化分析工具。
- **设计原则**：
  - **绝对隐私**：无网络权限（清单文件不声明 `INTERNET`），所有事件流与统计结果本地持久化。
  - **低开销**：依托系统底层事件索引，按需查询与本地轻量计算，杜绝无意义的高频后台轮询。
  - **数据保真**：保留会话级（Session-level）原始时间戳，支持追溯应用切换时序，而非仅展示聚合总时长。

## 2. 权限与系统交互规范

### 2.1 权限矩阵

| **权限声明**                                              | **权限类型**         | **用途与必要性**                                             |
| --------------------------------------------------------- | -------------------- | ------------------------------------------------------------ |
| `android.permission.PACKAGE_USAGE_STATS`                  | `appops` 特殊权限    | **核心权限**。用于通过 `UsageStatsManager` 获取前台切换事件流与聚合时长。 |
| `android.permission.POST_NOTIFICATIONS`                   | 运行时权限 (API 33+) | 发送限额预警、每日总结报告通知（可选）。                     |
| `android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 特殊权限             | 保障后台定期同步与限额检测任务不被系统 Doze 模式中断（仅在开启限额提醒时引导）。 |

### 2.2 权限引导与容灾流程

1. **冷启动鉴权**：App 启动时通过 `AppOpsManager.checkOpNoThrow` 校验是否已获得 `OPSTR_GET_USAGE_STATS`。
2. **引导页（Gate Page）**：
   - 未授权时，阻断主功能展示，呈现清晰的权限原理图解（声明仅本地读取、不收集隐私）。
   - 点击提供跳转 Intent：`Settings.ACTION_USAGE_ACCESS_SETTINGS`。
3. **返回状态刷新**：在 `onResume` 中重新校验，授权即刻进入主界面；若用户返回仍未授权，继续展示友好引导，禁止崩溃或空白。

## 3. 信息架构与页面功能设计

应用分为 4 个主要核心板块：**仪表盘（今日）**、**时间流（轨迹）**、**趋势（多维）**、**设置与规则（管理）**。

### 3.1 板块一：今日仪表盘 (Dashboard)

作为默认主页，承载用户对“今天手机怎么花掉的”第一视觉反馈。

- **顶部总览卡片 (Summary Card)**：
  - **核心指标**：今日累计亮屏时长（小时/分钟）、设备解锁次数、应用启动总频次。
  - **与昨日对比**：基于当前时刻，动态显示比昨日同时段快/慢的百分比（如：“比昨日此时少用 34 分钟”）。
  - **24小时时间分布直方图**：横轴 0~24 点，纵轴为每小时内使用分钟数（最高 60min），直观呈现波峰时段（如深夜、午休）。
- **应用排行列表 (Rank List)**：
  - **筛选/排序维度切换**：按“使用时长降序”、“启动次数降序”、“应用名称”。
  - **列表项视觉规范**：
    - 应用图标（带缓存降级逻辑） + 应用名称。
    - 进度指示条（以 Top 1 应用时长作为 100% 相对基准）。
    - 右侧显示绝对时长与启动次数（如：`2小时15分 · 38次`）。
    - 标记标签（属于哪个自定义分类，如“社交”）。
  - **点击交互**：点击任意 App 项展开/进入**应用详情子页面**：
    - 展示该 App 今日各时段使用分布柱状图。
    - 平均每次会话时长（单次使用中位数与均值）。
    - 今日每次打开的具体起止时间段列表。

### 3.2 板块二：时间轨迹流 (Timeline)

以时序瀑布流（Waterfall Stream）的形式，完整还原用户的操作序列。

- **视图交互**：
  - 支持顶部日期选择器（按天滑动切换）。
  - 按时间先后顺序由上至下展示时间轴节点。
- **节点数据聚合与展示逻辑**：
  - **单次会话块 (Session Block)**：
    - 展示起始时间与结束时间（例如 `14:20 - 14:45`）。
    - 应用图标、名称、本次连续使用时长（`25 分钟`）。
  - **系统状态标记**：
    - 两段使用之间若屏幕处于关闭状态，自动插入**息屏锁屏占位条**（例如 `🔒 息屏休息 1小时10分钟`）。
  - **微小片段折叠 (Noise Filtering)**：
    - 由于复制验证码、快速误触切换等操作会产生大量小于 5 秒的事件，UI 默认提供“折叠短于 10 秒的操作”开关，将其折叠为“3 个快速切换记录”，点击展开明细，避免列表过度碎片化。

### 3.3 板块三：趋势与分类统计 (Analytics)

用于中长期行为分析与习惯纠偏。

- **周期选择器**：日视图、周视图（周一至周日）、月视图、自定义区间。
- **分类透视 (Category Breakdown)**：
  - **分类饼图 / 堆叠条形图**：展示社交、办公、影音、游戏、工具等维度的占用比例。
  - **分类详情**：展开每个分类，可查看其内部各子应用的贡献占比。
- **趋势折线图**：
  - 展示所选周期内每日屏幕总时间的起伏曲线。
  - 叠加展示每日解锁次数的波动柱状。
- **深度洞察指标**：
  - **拿起手机后首次动作分析**：统计解锁屏幕后，最常第一时间打开的应用 Top 3。
  - **最长连续使用记录 (Longest Run)**：单次不间断使用同一应用的最长连续时长及发生的时段。

### 3.4 板块四：规则、过滤与数据管理 (Settings)

- **白名单与过滤规则**：
  - **桌面与系统组件排除**：默认且允许用户自定义排除桌面 Launcher（如系统桌面、Nova 等）、输入法、系统 UI，避免桌面停留扰乱生产力统计。
  - **应用黑名单**：可勾选“完全不统计某些 App”，其事件在入库阶段即被丢弃。
- **应用分类管理**：
  - 内置标准分类（系统默认基于应用元数据匹配）。
  - 支持用户手动更改某个 App 的归属分类（如将“微信”从“社交”改为“工作”）。
- **数据存储与导出**：
  - **本地存储策略**：配置历史明细保留时长（30天 / 90天 / 永久）。超期明细自动聚合为“日摘要数据”，并清理底层的原始毫秒级 Event，平衡 SQLite 数据库体积。
  - **全量导出**：支持将数据导出为结构化的 `CSV` 或 `JSON` 文件，支持保存至本地存储或调用系统分享面板。
  - **数据清空**：支持一键清空本地统计数据库。

## 4. 数据模型与清洗计算规格

### 4.1 核心数据结构设计

```
[UsageSession 会话模型]
- id: Long (主键)
- packageName: String (包名)
- appName: String (快照缓存名称)
- startTime: Long (毫秒时间戳)
- endTime: Long (毫秒时间戳)
- duration: Long (持续毫秒数)
- dateTag: String (形如 "2026-11-08"，用于索引分区)

[DailySummary 日聚合模型]
- dateTag: String (主键)
- totalScreenTime: Long (总亮屏时长)
- unlockCount: Int (解锁次数)
- appUsageJson: String (存储 key: packageName, value: duration)

[AppMetadata 应用配置模型]
- packageName: String (主键)
- category: String (自定义类别)
- isIgnored: Boolean (是否忽略统计)
- customName: String? (用户自定义备注)
```

### 4.2 原始事件（UsageEvents）清洗逻辑

系统 `UsageStatsManager.queryEvents(start, end)` 返回的是离散的系统状态序列，必须通过状态机算法还原为成对的 `Session`：

1. **事件配对规则**：
   - 识别 `UsageEvents.Event.ACTIVITY_RESUMED`（切到前台）标记为 Session 开始。
   - 识别紧随其后的 `UsageEvents.Event.ACTIVITY_PAUSED` 或 `ACTIVITY_STOPPED` 标记为 Session 结束。
2. **跨午夜（00:00:00）处理逻辑**：
   - 若用户从 `23:45` 使用应用至次日 `00:30`：
   - 数据入库算法必须以当日 `23:59:59.999` 为界，将原始事件硬切断为两段：前一段 15 分钟归入前一日数据，后一段 30 分钟归入次日数据。严禁将 45 分钟全部叠加在任意单一日。
3. **异常事件补齐与兜底**：
   - **系统关机/崩溃/进程杀死**：若遇到 `ACTIVITY_RESUMED` 后无对应的 `PAUSED` 事件，且后续直接出现了 `DEVICE_SHUTDOWN` 或时间断层：以断层前最后一个有效事件或预设上限（如单次连续无操作最大 2 小时）作为结束锚点截断，防止产生数百小时的“幽灵时长”。
   - **分屏/悬浮窗多任务场景**：若系统触发两个 App 均处于活跃状态，以当前获得用户焦点（Focus/Top Resumed）的应用作为独占统计对象，或在数据结构上标记 `isMultiWindow=true`，默认不重复计算系统总屏幕时长。

## 5. UI/UX 状态规范与异常处理

1. **冷启动加载性能**：
   - 查询大跨度时间线（如查最近 30 天明细）可能消耗数百毫秒 I/O。
   - 页面加载必须采用**分级加载策略**：优先从 SQLite 缓存的 `DailySummary` 读取并渲染图表骨架；后台异步协程执行 `UsageEvents` 的增量对齐与计算，计算完毕无缝刷新 UI（Skeleton Loading 骨架屏设计）。
2. **应用卸载与图标丢失**：
   - 统计历史中存在已被用户卸载的应用。
   - 获取 `ApplicationInfo` 失败时（`NameNotFoundException`），UI 端统一降级使用默认系统通用轮廓图标，标题展示为其原始包名（或使用数据库中最后一次记录的历史快照名），并在右侧标记浅灰字样“已卸载”。
3. **空状态处理 (Empty State)**：
   - 初次安装首日使用时，数据未跨整天，仪表盘图表需明确提示“正在积累统计数据，完整分析将于次日就绪”，折线图不可崩溃或产生畸变。
