# 统计与数据契约

这是页面、数据库、导出与测试共同遵守的统计基线。规则变更必须更新算法版本。

## 1. 时间与口径

- 原始时间以 epoch 毫秒保存，区间统一为 `[start, end)`。按相邻时间点切段，时长为 `end - start`。
- 保存事件采集时的时区信息；默认按当前选定的统计时区重建日期投影，初始为设备时区。界面标明时区。时区变化使相关日缓存失效，原始会话保留。
- 自然日边界由时区计算次日开始，支持 23/25 小时日。首版日界线固定午夜。
- 区间查询按交集裁剪，保留原会话 ID；跨日分配时长，开始次数只计在原会话开始所在日期。
- 比较“昨日此时”时按同一统计时区的当地时刻构造区间，检查双方覆盖情况。

| 指标 | 定义 |
| --- | --- |
| 屏幕交互时长 | SCREEN_INTERACTIVE 至 SCREEN_NON_INTERACTIVE 等明确终点区间的并集 |
| 手机使用时长（首页） | 屏幕交互且锁屏已解除的区间并集；锁屏状态不足部分单列 |
| 解锁次数 | 已知锁屏状态由显示转为隐藏的次数；首次观察到隐藏只建立状态 |
| 应用前台时长 | 应用活跃区间与已知手机使用区间交集的并集；状态不足部分单列为推算 |
| 应用使用次数 | 应用级连续会话开始次数，界面称“使用次数” |
| 手机使用轮次 | 已解锁且可交互的连续设备区间数量 |
| 最长应用会话 | 单应用完整连续会话长度，注明跨日部分 |
| 最长一轮手机使用 | 连续设备使用区间长度，与单应用会话分别展示 |

桌面等系统用时保留为单独桶，默认从应用排行隐藏；设备总时长保持原口径。并发情况下每应用分别计时，应用合计可能超过设备使用并集，界面给出口径解释。

## 2. 事件还原

输入包含时间、类型、包名、Activity 类名、可获得的实例标识与原始顺序；实例标识属于可选能力。系统没有提供的字段保存为空，并记录设备接入能力。

分别维护屏幕状态、锁屏状态、Activity 活跃集合与设备启动周期。状态值允许 unknown。

1. RESUMED 激活对应 Activity，PAUSED 结束相应活跃区间；STOPPED 作为补充清理。仅关闭匹配的实例/类名，避免旧 Activity 延迟暂停误关新页面。
2. 同包 Activity 的连续过渡合成为应用会话；默认过渡容差 1 秒，要求中间无其他应用、息屏或锁屏边界。容差区间标为桥接推算，单列其时间并支持查看，规则通过真机样本调整。
3. 新应用 RESUMED 后旧应用尚未 PAUSED 的重叠先保留；短暂生命周期交错与持续并发分别标记。仅凭使用事件无法确认分屏布局时，标记“并发前台”而不猜测屏幕几何或焦点。
4. 屏幕关闭、锁屏、明确关机边界终止对应计时。DEVICE_SHUTDOWN 的时间采用系统记录并标记语义为持久化边界。
5. 重启使用 DEVICE_STARTUP 等事件建立新周期；设备能力不足时保留来源状态，避免跨周期接续。
6. 采集进程退出不构成其他应用结束。下次查询恢复状态并重新计算尾部。
7. 当前持续会话为 open，会话预览截至查询时刻，数据库不将此时刻视为最终关闭。
8. 状态无法可靠接续时产生 unknown 区间；存在合理推算依据时保存 inferred 标记与原因。使用时长长于两小时仍按实际事件计算。

首页主指标采用已观察区间，推算部分单独给出“另有约 X 分钟待确认”；展开可见依据。未知区间不自动分配给前一个应用。

## 3. 采集、覆盖与去重

- 首次授权按日分批回填系统可查询范围，记录首次观察时间与覆盖来源。请求成功只代表完成查询；空响应、保留边界及缺失起始状态分别记录。
- 默认每小时发起可延迟补采，打开应用、手动刷新、授权恢复时补采。周期仅为目标频率。
- 初始重叠回查 30 分钟；存在 open 状态时从最近可靠状态检查点回放。查询窗口按事件量分批，极长会话从检查点恢复，避免每次扫描全部历史。
- 水位推进与事件写入在同一事务提交。前台与后台共用同步互斥锁，重复请求合并。
- 使用事件没有稳定全局 ID。对重叠区间按来源、时间、类型、包名、类名、实例标识构建指纹，并保存同值事件的重数；以区间替换/多重集对齐实现幂等，保留同毫秒事件顺序。
- 派生会话按重建区间事务替换；覆盖边界的会话连同上下文一起处理。用户标注按时间绑定，不依赖会话行主键。
- 覆盖状态区分 queried（已查询）、observed（有事件依据）、inferred（推算）、gap（明确缺失）、summaryOnly（仅摘要），并保存原因。查询完成范围与事实覆盖范围分别存储。

## 4. 分类、隐藏与隐私排除

应用分类按平台本身的属性，例如Bilibili为“影音娱乐”，不识别具体内容或推断用户是在学习还是消遣。自动分类优先使用独立包名规则表，再读取Android系统类别；都无法匹配时保留未分类。用户选择覆盖自动结果，可恢复自动，也可明确保留未分类。类别包括影音娱乐、社交通讯、游戏、学习教育、效率办公、生活服务、资讯阅读、出行导航、工具和其他。

日/周分类报表先按同一应用合并重叠会话，再按类别汇总，与应用构成采用相同的前台口径（含推算）。分屏应用分别计时，因此合计可超过设备使用时长；隐藏与隐私排除应用不参与。时段标注和备注由用户自行掌握，不影响应用类别或分类统计。

元数据分别保存自动类别和可空的用户覆盖；旧的默认用途字段只为历史数据与备份兼容保留，不再用于自动分类。Room从1迁移至2时新增字段，保留原记录、设置与备注；旧JSON备份可读取，新的类别字段参与备份恢复。应用版本号保持不变。

“从排行隐藏”改变展示与过滤结果；“停止保存此应用明细”改变采集内容。隐私排除包仍作为切换边界使用，落库前去除包名、类名等身份，保留匿名排除时段，防止前一个应用被错误续计。数据库、导出、日志采用同一排除策略。首次开启询问处理已有历史：默认同步清理该应用已有明细及关联缓存，用户可选择仅未来生效。

默认不记录原始内容，后台诊断日志也避免包名、个人备注和完整轨迹。使用数据不上传；联网权限仅用于用户要求的 GitHub 更新检查与下载。关闭系统自动备份/设备迁移中的应用数据复制，以本地显式导出备份为主要途径。

## 5. 保留、导出与恢复

- 默认原始事件保留 90 天；应用会话、设备区间、日摘要、标注长期保存。清理原始事件前确保派生记录已提交，并标记可重新计算的最早时间。
- 设置中展示空间占用与各类保留策略。摘要保存版本、时区、分类版本与生成时刻。
- 用户主动清理会话前确认受影响范围，保留摘要并标明“仅摘要”；之后无法支持的小时分析、重新分类在界面说明具体区间。
- JSON 提供完整逻辑备份：schemaVersion、algorithmVersion、时区、覆盖记录、会话、区间、标注、配置及保留的事件。CSV 提供会话表与日统计等独立表，含毫秒时间、可读时间、来源与质量标记；防止文本字段被表格软件当公式执行。
- 通过系统文件选择器保存，避免申请广泛存储权限。分享由用户主动调用系统面板，提示分享内容包含应用使用记录。
- 恢复先校验版本、区间与引用，显示导入预览；第一版采用整库替换，事务完成后生效。失败保留原数据。
- 清空时选择“清空并重新采集”或“清空并暂停采集”。重新采集设置新的起点，防止旧记录被自动回填。

## 6. 日与自然周报表

周区间按统计时区的周一开始至下周一开始计算；当前周的有效终点为当前时刻。按自然日裁剪的贡献之和必须等于整周聚合，跨周会话保留原始区间和标识。小时与四小时时段由本地时间构造边界，夏令时日允许 23/25 小时，不能固定假设每周 168 小时。

趋势、热图的设备时长使用设备区间并集；应用图表对同应用区间先取并集，再按应用分别累计。占比以展示的应用前台时长之和为分母，不能以设备时长作分母；匿名排除不进入具名构成，隐藏规则仅改变展示。

未查询、未知、部分覆盖、确有状态依据的零值和未来日期分别处理；未来不能投影为零值。已记录天数表示当天存在设备状态证据，并不等价于全天完整覆盖。不完整周暂不提供跨周百分比变化与日均值，避免因缺失和本周未结束误导用户。测试须覆盖周一边界、跨年周、夏令时、重复片段去并集与日周可加性。
