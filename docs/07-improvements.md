# 功能打磨与后续建议

2026-11-08。本轮围绕“看懂 → 决定 → 行动 → 复盘”，优先解决记录与操作的问题，再添加有趣的呈现。

## 本轮实现

- 设置首页只保留分组入口。应用列表放入“应用管理”，支持搜索、已隐藏/已排除筛选，应用分类、隐私与单应用目标在应用设置中修改。
- 采集状态、数据管理、外观、版本更新、隐私和项目反馈各有独立页面。采集诊断放在需要排查时进入的页面，不占报表主体。
- 每日手机用时目标和单应用目标保存在本机，关闭时不展示进度；不强制拦截，不以连续打卡惩罚偶尔超时。
- 日/周分类统计按应用本身的类别汇总，例如Bilibili归影音娱乐，不推断使用目的。类别来自本地规则和系统元数据，允许用户覆盖；时段备注不改变应用类别。分类用时与应用构成一致，分屏可分别计时。
- 独立记录页提供每日复盘与随手记，支持自动保存草稿、历史搜索、日期与类型筛选、置顶、删除撤销和系统分享。复盘中的明日行动可在今日与记录页完成或取消完成，周回顾显示复盘进度；备份包含全部记录状态。设计见 [记录与每日复盘](11-records-and-reflection.md)。
- GitHub 更新包括检测、版本说明、下载与进度、取消/重试、完整性和包签名校验、未知来源授权往返与系统安装。自动检查默认关闭，打开应用时最多每天检查一次，不自动下载。
- 桌面组件与未使用时段已实现：今日用时、最长未使用、小时分布、目标、可调尺寸与未使用详情。设计和统计边界见 [专项文档](10-widgets-and-away.md)。

## 下一步最值得投入

| 优先级 | 建议 | 具体使用方式 | 边界 |
| --- | --- | --- | --- |
| 高 | 一周小实验 | 选择“睡前少看15分钟”之类的一个变化，一周后比较相同时段 | 先确认两侧覆盖充分，不承诺因果 |
| 高 | 温和的晚间复盘提醒 | 用户选一个时刻，提醒查看当天并留下明天一个行动 | 默认关闭，开启时再申请通知权限，不要求常驻服务 |
| 中 | 月历视角 | 按天显示用时、复盘和目标，点某天查看报表 | 无记录与零值用不同符号，不用红色羞辱 |
| 中 | 自选周报图片 | 用户主动选日期与要展示的指标，导出一张简洁图片 | 默认不带应用名、备注或完整轨迹 |
| 后续 | 私人的时间花园 | 每周为自己选的行动添一个小变化，允许暂停和调整 | 不把使用更少等同于更有价值，不设置断签清零 |

## 比新玩法更优先的工程工作

完善状态检查点、时钟跳变隔离、分页与保留策略，并在真实手机核对重启、锁屏、分屏、厂商后台和一周覆盖。没有可靠数据时，不给出自律评分、同比结论或“节省了多少时间”的断言。
